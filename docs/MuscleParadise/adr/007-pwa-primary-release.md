# ADR-007 — PWA مشترک، رابط اصلی انتشار اول

> وضعیت: **Accepted — تصمیم دامنهٔ مالک؛ اجرا/Go-No-Go تأیید نشده** | تاریخ: **2026-11-23 UTC** | مالک تصمیم: مالک پروژه | مرتبط: ADR-006، `D-01`، `D-10`، `PWA-00` و handoff v2.0.0

## زمینه و مسئله

ADR-006 جهت ساخت یک PWA مشترک React روی `mp-app/studio/` و حفظ Flutter/Android را ثبت کرده بود، اما baseline کلاینت انتشار اول را باز می‌گذاشت. مالک در پاسخ‌های ثبت‌شدهٔ question box مشخص کرد PWA مشترک برای **عضو و کادر** رابط اصلی انتشار اول باشد. این تصمیم، بستهٔ ۵۰ میکرولوپی را به محدودهٔ کاری تبدیل می‌کند؛ کامل‌شدن آن، پذیرش انتشار یا QA محصول را ثابت نمی‌کند.

## معیارهای تصمیم

- مرجع واحد و قابل‌آزمون برای تجربهٔ عضو و کادر، بدون ساخت اپ React موازی؛
- حفظ مسیر Flutter/Android، تاریخچه، مستندات، تست‌ها و CI؛
- حفظ سیاست جاری تک‌باشگاه، شش نقش، داده، پرداخت، حریم و امنیت، بدون تغییر ضمنی؛
- امکان ارزیابی همهٔ سفرهای اصلی و ماتریس مرورگر/device پیش از release؛
- مرزبندی روشن بین انتخاب baseline و مجوز production/release.

## گزینه‌های بررسی‌شده

1. Android عضو + Studio کادر به‌عنوان رابط اصلی نسخهٔ اول و PWA فقط آینده — انتخاب نشد.
2. PWA مشترک فقط برای یکی از دو گروه — انتخاب نشد.
3. یک PWA مشترک React برای عضو و کادر، توسعه‌یافته از Studio موجود؛ حفظ Flutter/Android ولی خارج از مسیر اصلی انتشار اول — انتخاب شد.

## تصمیم مالک

1. **کلاینت اصلی انتشار اول:** یک PWA مشترک React برای عضو و کادر، بر پایهٔ `mp-app/studio/`. اپ React دوم ساخته نشود.
2. **آثار native:** `mp-app/client/`، Android/Flutter، تاریخچه، مستندات، تست‌ها و CI حفظ شوند؛ حذف یا خاموش‌کردن آن‌ها مجاز نیست. Android/Flutter در این تصمیم کلاینت اصلی انتشار اول نیستند.
3. **هدف آزمون مرورگر:** Android Chrome برای عضو؛ Chrome/Edge دسکتاپ برای کادر. این فقط انتخاب ماتریس هدف است، نه اثبات سازگاری؛ نسخه‌های دقیق، مدل‌های دستگاه و آزمون فیزیکی هنوز مشخص/اجرا نشده‌اند.
4. **سازمان و نقش:** تک‌باشگاه؛ شش نقش فعلی حفظ شوند. این ADR مجوز multi-tenancy، کاهش نقش‌ها، تغییر grant یا migration دسترسی نیست.
5. **داده و میزبانی:** SQLite فعلاً مبنا بماند و نیاز PostgreSQL فقط پس از benchmark/trigger مستند بررسی شود. جهت زیرساخت سرور محلی باشگاه با ورودی HTTPS است؛ نام میزبان، دامنه، اپراتور، بودجه، backup خارج‌میزبان، restore و RPO/RTO بازند.
6. **تجارت و قابلیت‌های حساس:** کارت‌به‌کارت با تطبیق انسانی؛ فروشگاه عضو نمایش‌محور؛ حضور با QR و بدون تشخیص چهره؛ راهنمای سلامت بدون ادعای پزشکی؛ عکس پیشرفت بدن خارج از scope انتشار اول. پرداخت واقعی یا merchant در این تصمیم مجاز نمی‌شود.
7. **دامنهٔ انتشار:** همهٔ جریان‌های اصلیِ TODO باید پیش از انتشار واقعی تکمیل و با شواهد همان نسخه پذیرفته شوند؛ pilot ناقص جایگزین آن نیست.
8. **مدل AI و اختیار اجرا:** API/inference بیرونی یا ارسال کد/داده به آن استفاده نشود. پس از فرمان «ادامه بده»، کار محلیِ کد/تست/مستندات روی شاخهٔ فعال می‌تواند بدون تأییدهای روتین ادامه یابد؛ این اختیار شامل commit/push/PR/merge/release/deploy، پس‌زمینهٔ بین پیام‌ها، production، دادهٔ واقعی یا secret نیست.

## پیامدها و گیت‌های باز

- ✅ تعارض baseline کلاینت برای انتشار اول حل شد؛ ADR-006 برای جهت shared React همچنان معتبر است و این ADR فقط دامنهٔ انتشار را دقیق می‌کند.
- ✅ پاسخ‌های OQ-01…OQ-10 در [دفتر پرسش و پاسخ مالک](../architecture/owner-decision-questionnaire-2026-11-23.fa.md) ثبت شده‌اند. فهرست کامل ۵۰ کارت و Motion Kit در TODO واحد آمده است.
- ⚠️ هیچ‌یک از این انتخاب‌ها ادعای تکمیل UI، PWA installability، parity عضو/کادر، runtime، security, privacy, browser/device E2E یا آمادگی release نیست.
- 🔒 owner اعلام کرده reviewer مستقل حقوقی/پزشکی/مالی ندارد. گیت‌هایی که بازبینی مستقل لازم دارند تا دریافت شاهد همان‌طور `UNKNOWN/NOT_RUN` می‌مانند؛ قابلیت‌های حساس خارج از مرز بالا اضافه نشوند.
- 🔒 Android signing key در تاریخچهٔ عمومی افشاشده گزارش شده است. مالک گفته APK انتشار به کاربران داده نشده؛ این موضوع کلید را امن نمی‌کند. تا چرخش/مدیریت امن و بررسی گیت، release build اندروید ساخته نشود.
- 🔒 وظیفهٔ آفلاین/کش حساس، policy نشست، ماتریس کامل route×role×permission، پرداخت live، database migration، deployment و backup/restore نیازمند کار/گیت جدا هستند؛ این ADR آن‌ها را تصویب نمی‌کند.

## پیاده‌سازی و راستی‌آزمایی

- **ریشهٔ PWA:** `mp-app/studio/`؛ کد فعلی و تغییرهای dirty به‌تنهایی پذیرش PWA مشترک نیستند.
- **ماتریس پایه:** Android Chrome برای عضو؛ Chrome/Edge دسکتاپ برای کادر. نسخه و دستگاه فیزیکی بعداً pin و آزموده می‌شوند.
- **Backlog:** [TODO واحد، افزودهٔ PWA/UI/UX کامل](../TODO-2026-11-16.md#pwa-ui-ux-full-backlog-2026-11-23)؛ ۵۰ parent اصلی PWA از `PWA-00` تا `PWA-56` با شناسه‌های canonical.
- **شواهد فعلی:** package handoff v2.0.0 با `PACKAGE_OK_NOT_QA` و inventory ایستا بررسی شده؛ تمام ۵۰ کارت در artifact منبع `evidence_status=NOT_RUN` داشتند. Motion Kit v1.1.0 بازبینی/موجودی مستند دارد؛ این‌ها Product QA نیستند.
- **تغییر محصول در همین ADR:** `NOT_RUN`؛ هیچ claim از پیاده‌سازی/تست/انتشار صادر نمی‌شود.
- **Go/No-Go:** فعلاً `NO-GO` تا تکمیل جریان‌های اصلی و گیت‌های امنیت/حریم/عملیات/device و ارائهٔ شواهد روی artifact دقیق.

## ارتباط با تصمیم‌های دیگر

- **Clarifies:** ADR-006؛ shared React همچنان مبناست، اکنون PWA مشترک عضو/کادر برای انتشار اول نیز صریحاً انتخاب شده است.
- **Supersedes:** baseline قدیمیِ «Android عضو + Studio کادر رابط اصلی انتشار اول» فقط در دامنهٔ کلاینت اصلی؛ فایل‌های Android/Flutter حفظ می‌شوند.
- **Does not supersede:** تصمیم‌های پرداخت دستی، تک‌باشگاه، شش نقش، SQLite فعلی، QR، حد و مرز ادعای پزشکی، حفاظت از داده و ممنوعیت انتشار/عملیات بدون گیت.
- **Superseded by:** ندارد.
