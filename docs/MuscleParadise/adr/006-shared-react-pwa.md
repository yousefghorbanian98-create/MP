# ADR-006 — PWA مشترک React بر پایهٔ Studio

> وضعیت: **Accepted — دامنه‌محدود** | تاریخ دستور جهت UI: **2026-11-23 UTC** (منبع: دستور کاربر برای PWA-00 در نشست Arena؛ فقط انتخاب یک PWA مشترک React روی Studio و حفظ کلاینت‌ها) | تاریخ ثبت/اصلاح این metadata: **2026-11-24 UTC** | مالک تصمیم: مالک پروژه/کاربر صادرکنندهٔ دستور (نام شخصی در مخزن ثبت نشده) | مرتبط: `PWA-00` در بستهٔ handoff v2.0.0، `D-01`، `D-10`

این پذیرش فقط جهت محدود پلتفرم رابط کاربری را ثبت می‌کند؛ تأیید انتشار، پذیرش محصول، پنج سفر، QA، تأیید نهایی انسانی یا merge نیست. در زمان ثبت اولیه، `D-01` و `D-10` باز بودند؛ یادداشت تاریخ‌دار پایین‌تر روشن می‌کند که ADR-007 بعداً baseline کلاینت (`D-01`) را تعیین کرد و معیارهای پذیرش (`D-10`) همچنان گیت جدا هستند.

## زمینه و مسئله

محصول مسیر React موجود در `mp-app/studio/` و کلاینت Flutter/Android عضو دارد. **در زمان نگارش اولیهٔ این ADR** اسناد انتشار وقت Android برای عضو و پنل وب برای کارکنان را baseline انتشار اول ثبت می‌کردند؛ برنامهٔ کلان 2026-11-23 نیز آن زمان تعارض baseline با هدف PWA مشترک را حل‌نشده می‌دانست. دستور ثبت‌شده در همان snapshot جهت UI را تعیین کرد: PWA مشترک React با گسترش Studio موجود، نه اپ React دوم.

این ADR فقط جهت پلتفرم رابط کاربری را ثبت می‌کند. در نسخهٔ اولیه، جایگاه انتشار در `D-01` و معیارهای پذیرش در `D-10` باز مانده بود؛ ADR-007 بعداً `D-01` را برای کلاینت اصلی روشن کرد و `D-10`/Go-No-Go را جداگانه باز گذاشت. وجود manifest، Service Worker یا صفحات فعلی به‌تنهایی تکمیل PWA مشترک، parity عضو/کارکنان، نصب‌پذیری واقعی یا QA انتشار را اثبات نمی‌کند.

## معیارهای تصمیم

- استفاده از Studio React موجود و پرهیز از ایجاد محصول/ریشهٔ React دوم؛
- حفظ Flutter/Android و سابقهٔ آن‌ها، مستندات و تست‌ها، گیت‌های CI، workflow فعلی Flutter Web و Electron؛
- جداسازی جهت UI از تصمیم‌های اختیار/داده/عملیات؛
- ثبت روشن موارد حل‌نشدهٔ baseline انتشار، بدون بازکردن دوبارهٔ جهت قطعی React.

## گزینه‌های بررسی‌شده

1. **ساخت اپ React جداگانه برای عضو:** رد می‌شود؛ با جهت یک PWA مشترک و گسترش Studio سازگار نیست.
2. **گسترش `mp-app/studio/` به PWA مشترک React:** انتخاب‌شده برای مسیر UI؛ صفحات کارکنان در همین محصول می‌مانند و تجربه‌های عضو تدریجی به آن افزوده می‌شوند.
3. **جایگزینی یا خاموش‌کردن Flutter/Android یا Flutter Web:** انتخاب نشده و مجاز نیست؛ حفظ کد و گیت‌های موجود صریحاً لازم است.

## تصمیم

1. مسیر هدف UI، **یک PWA مشترک React بر پایهٔ `mp-app/studio/` موجود** است؛ اپ React دوم مانند `mp-app/pwa-member/` ساخته نمی‌شود.
2. `mp-app/client/` و مسیر Flutter/Android، تاریخچه، مستندات، تست‌ها و گیت‌های CI حفظ می‌شوند. workflow فعلی Flutter Web در `.github/workflows/web.yml` بی‌تصمیم خاموش یا با React جایگزین نمی‌شود. فایل‌ها و بسته‌بندی Electron نیز حفظ می‌شوند.
3. این تصمیم فقط جهت UI را مشخص می‌کند و مجوز تغییر نقش‌ها یا grants، دیتابیس یا tenant، پرداخت، نشست یا سیاست آفلاین/cache نیست. هر یک، تصمیم و کارت جداگانه می‌خواهد.
4. در نسخهٔ اولیهٔ این ADR دو موضوع باز ثبت شده بود (وضعیت جاری آن‌ها را در یادداشت هم‌راستاسازی بخوانید):
   - **D-01:** جایگاه PWA در baseline انتشار اول نسبت به Android عضو + Studio کارکنان؛ بعداً با ADR-007 پاسخ داده شد.
   - **D-10:** جریان‌های انتشار، نقش‌ها/دستگاه‌ها/مرورگرها، زبان و RTL و حداقل شواهد پذیرش؛ همچنان گیت مستقل پذیرش است.

جهت React در بندهای ۱ و ۲ تصمیم‌گرفته‌شده است و برای تأیید دوباره مطرح نمی‌شود. انتخاب PWA در ADR-007، گیت D-10 یا Go/No-Go را نمی‌بندد.

## پیامدها

- ✅ سرمایه‌گذاری روی یک پوستهٔ React مشترک و حفظ تجربه‌های فعلی کارکنان؛ امکان انتقال تدریجی قابلیت‌های عضو.
- ✅ حذف ریسک ایجاد اپ React دوم و حفظ هم‌زمان مسیرهای native و workflowهایشان.
- ⚠️ **در زمان ثبت اولیهٔ ADR-006** نباید از این جهت UI، جایگاه انتشار نتیجه گرفته می‌شد. ADR-007 بعداً baseline کلاینت PWA را تعیین کرد؛ implementation/parity و پوشش انتشار همچنان اثبات نشده‌اند.
- ⚠️ تکمیل routeها، نشست، نقش/مالکیت، API، نصب/Service Worker، accessibility، parity و آزمون دستگاه شواهد و کارت‌های جداگانه می‌خواهند.
- 🔒 هیچ مجوزی برای تغییر backend، نقش/grant، DB/tenant، پرداخت، storage نشست، offline write/cache، deploy یا release صادر نمی‌شود.

## پیاده‌سازی و راستی‌آزمایی

- **ریشهٔ هدف:** `mp-app/studio/`؛ این ADR تغییر کد محصول نیست.
- **آثار محفوظ:** `mp-app/client/`، Android/Flutter، اسناد و تست‌هایشان، workflowهای Flutter/Android و `.github/workflows/web.yml`، نیز `mp-app/studio/electron/`.
- **تغییر محصول در این کارت:** `NOT_RUN`؛ ادعای PWA مشترکِ پیاده‌شده یا انتشارشده وجود ندارد.
- **راستی‌آزمایی همین تغییر مستنداتی:** نتیجه‌ها و SHAهای واقعی در [شواهد PWA-00](../architecture/session-decisions-2026-11-23/PWA-00-EVIDENCE.fa.md) ثبت می‌شوند. گیت مستندات، QA/runtime محصول محسوب نمی‌شود.

در زمان ثبت اولیهٔ این ADR، `D-01` (جایگاه PWA در baseline انتشار اول) و `D-10` (معیارهای پذیرش انتشار) باز بودند. تصمیم بعدیِ [ADR-007](007-pwa-primary-release.md) `D-01` را برای دامنهٔ کلاینت روشن کرد: PWA مشترک React روی Studio، رابط اصلی انتشار اول برای عضو و کادر است؛ Flutter/Android حفظ می‌شود. بنابراین متن‌های تاریخی پایین‌تر که `D-01` را باز می‌خوانند، وضعیت زمان ثبت ADR-006 هستند و نباید بر خلاف ADR-007 به‌عنوان تصمیم جاری تعبیر شوند.
