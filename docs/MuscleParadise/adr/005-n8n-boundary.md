# ADR-005 — مرز محدود و غیرمحصولی n8n

> وضعیت: **پذیرفته** | تاریخ: 2026-11-16 | چرخه: M63 | تصمیم‌گیرنده: کاربر

## زمینه

در PRD و طرح تولید، n8n قبلاً برای یادآوری تمدید، پیامک، گزارش هفتگی و همگام‌سازی کمپین پیشنهاد شده بود. این دامنه با معماری و کنترل مستقیم MP روی هویت، پرداخت و دادهٔ عضو سازگار نیست. در بازبینی این شاخه، هیچ instance یا اتصال n8n در کد محصول پیدا نشد. همچنین مجوز خود n8n، **Sustainable Use License** است؛ آن را نباید MIT یا مجوز OSI دانست. مجوز هر template یا ابزار پیرامونی نیز جداست.

## تصمیم

n8n در MP **ابزار اختیاریِ بیرونی و غیرمحصولی** است؛ نصب، dependency، instance، credential یا integration در این چرخه ایجاد نمی‌شود.

### موارد مجاز

1. **اعلان read-only از وضعیت GitHub Actions به تیم**، فقط در صورت ایجاد instance و بررسی امنیتی/مجوزی جداگانه:
   - خواندن فقط metadata لازمِ run/check (نام workflow، شناسهٔ run، نتیجه، شاخه/ref و URL همان run) با دسترسی محدود به repository و `actions:read`؛ فقط درخواست‌های `GET`.
   - پیام حداقلی به کانال تیمیِ موردتأیید؛ بدون log، artifact، source، payload عضو، secret یا دادهٔ پرداخت.
   - هیچ مجوز `contents:write`, `actions:write`, `workflows`, `deployments`, `packages:write`, issue/PR write یا امکان dispatch/rerun/cancel ندهید. credential نوشتنی CI/GitHub را به n8n نسپارید.
   - اعلان‌گر نه گیت CI را جایگزین می‌کند و نه نتیجهٔ CI را تغییر می‌دهد.
2. **پشتیبان‌گیری GitHub از workflowهای خود n8n**، فقط اگر instance واقعاً راه‌اندازی شده باشد و تصمیم اجرایی/حقوقی جداگانه ثبت شود:
   - مقصد باید repository خصوصی و دسترسی آن محدود به نگه‌دارندگان مشخص باشد؛ credential اختصاصی فقط به همان مقصد و کمترین مجوز لازم محدود شود.
   - export پیش از ذخیره‌سازی بازبینی/پاک‌سازی شود. credential value، token، secret، دادهٔ اجرا، دادهٔ عضو/پرداخت، binary، webhook secret و pinned test data ذخیره نشود؛ URL، hostname، expression، مقدار ثابت، نام/ID credential و metadata هم ممکن است حساس باشند.
   - فقط workflowهای لازم صادر شوند؛ نگهداری، رمزنگاری، rotation و دسترسی به backup ثبت شود. Backup خودکار فعلاً **فعال نیست** و تا وجود instance صرفاً گزینهٔ آینده است.

### موارد ممنوع برای n8n

- منطق اصلی محصول یا محاسبه/تصمیم business؛ پرداخت، callback یا تأیید/تسویه؛ هویت، نشست یا RBAC؛ دسترسی، پردازش یا انتقال دادهٔ عضو/بیومتریک.
- یادآوری، اعلان یا کمپین محصولی برای عضو؛ این منطق باید در بک‌اند MP و مسیرهای مصوب خودش بماند (APScheduler/سرویس اعلان MP)، نه در n8n.
- تغییر خودکار مخزن (نوشتن/commit/push)، تغییر workflowهای GitHub، اجرای release، ساخت/انتشار package یا deploy/rollback محصول.
- import یا اجرای خودکار templateهای عمومی بدون بازبینی رفتار، محتوا و مجوز جداگانه.

## مجوز و درگاه اجرا

- پیش از هر self-host تجاری/توزیعی، متن جاری Sustainable Use License و شرایط استفادهٔ موردنظر حقوقی بررسی شود؛ self-host بودن را به‌تنهایی معادل «open source» یا اجازهٔ استفادهٔ تجاری فرض نکنید.
- ابزارهای مستقل مانند `n8n-as-code` و template catalog انتخاب یا dependency پروژه نشده‌اند؛ مجوز آن‌ها مجوز n8n را تغییر نمی‌دهد.
- هر راه‌اندازی instance یا اتصال آینده، ADR/تصمیم جدا، مدل تهدید، مالک عملیات، کنترل دسترسی، مدیریت secret، retention، مانیتورینگ و آزمون با دادهٔ مصنوعی می‌خواهد. تا آن زمان وضعیت **NOT DEPLOYED / NO CREDENTIALS / NO INTEGRATION** است.

## پیامدها

- ✅ اعلان احتمالی فقط read-only و جدا از داده و مسیر محصول است؛ پشتیبان‌گیری فقط برای خود instance و فقط در مخزن خصوصیِ بازبینی‌شده.
- ✅ یادآوری‌های عضو، پرداخت و منطق محصول در MP می‌ماند و نبود n8n مانع کار محصول نیست.
- ⚠️ اعلان CI و backup هیچ‌کدام در حال حاضر اجرا نمی‌شوند؛ برای فعال‌سازی‌شان باید instance، مجوزها و مقصد بازرسی شوند.
- ⚠️ لایسنس Sustainable Use و محتوای export نیاز به بازبینی مستقل دارند؛ این ADR مشاورهٔ حقوقی یا ادعای «بی‌نقصی» نیست.
