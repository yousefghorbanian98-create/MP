# ADR-003 — موتور قواعد قطعی به‌جای LLM برای تصمیم بار تمرینی

> وضعیت: **پذیرفته** | تاریخ: 2026-11-14 | چرخه: M02 | تصمیم‌گیرنده: architect (FINN) | قانون طلایی مرتبط: **G8**

## زمینه
هستهٔ تمایز MP، برنامه‌ریزی شخصی تمرین است. LLMها در تولید عدد (بار/ست/تکرار) غیرقابل‌اتکا و غیرقابل‌تکرارند و مسئولیت ایمنی (سلامت ورزشکار) را نمی‌پذیرند.

## گزینه‌ها
1. **موتور قواعد قطعی (ACSM/NSCA)** به‌عنوان تصمیم‌گیرنده + Ollama فقط برای توضیح/انگیزش + تأیید اجباری مربی
2. LLM به‌عنوان تصمیم‌گیرندهٔ اعداد (سریع، ولی غیرقطعی/غیرمسئول)
3. ترکیب مبهم (LLM عدد بسازد، قواعد فقط فیلتر) — مرز مسئولیت مبهم

## تصمیم
**گزینهٔ ۱.** جریان داده الزامی: `ورودی (ارزیابی/هدف/محدودیت) → موتور قواعد → اعداد (بار/ست/تکرار/پیشرفت) → تأیید مربی → نمایش عضو`. Ollama فقط متن توضیحی تولید می‌کند و هیچ عددی وارد pipeline نمی‌کند.

## دلایل
- قطعیت و بازتکرارپذیری خروجی (تست‌پذیر: همان ورودی = همان خروجی)
- مسئولیت‌پذیری: مربی انسانی داور نهایی (US-203)
- ایمنی: قواعد آسیب/محدودیت را hard-constraint می‌کنند (پرچم قرمز ارزیابی → محدودیت بار)

## پیامدها
- ✅ تست‌پذیری کامل موتور؛ اعتماد کاربر؛ انطباق با G8
- ⚠️ پیاده‌سازی قواعد نیازمند دامنه‌دانی (ACSM/NSCA) است → هر قانون = تست واحد + مرجع استاندارد در کد
- ⚠️ هر خروجی LLM باید از «لایهٔ عدد» جدا بماند (تست رگریشن مکانیکی: هیچ فیلد عددی از پاسخ LLM خوانده نمی‌شود)
