## قانون تغییر تصمیم

- ADR پذیرفته‌شده سند تاریخیِ چرایی تصمیم است؛ محتوای آن را برای همسان‌سازی با پیاده‌سازی بی‌صدا بازنویسی نکن.
- اگر تصمیم عوض شد، یک ADR تازه با وضعیت، تاریخ، مالک تصمیم، مسئله، گزینه‌ها، تصمیم، پیامدها و روش راستی‌آزمایی بساز؛ به ADR قبلی پیوند بده و آن را `Superseded` علامت‌گذاری کن.
- فرق «تصمیم پذیرفته‌شده» و «کد واقعاً پیاده‌شده» را حفظ کن. پیاده‌سازی را با منبع و تست بررسی کن؛ ADR مجوزی برای ادعای runtime نیست.
- شمارهٔ بعدی را پس از بررسی فهرست فایل‌ها انتخاب کن؛ شمارهٔ تکراری نساز.
