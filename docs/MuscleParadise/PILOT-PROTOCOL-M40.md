# پروتکل پایلوت ۷ روزه — حلقهٔ ارزیابی/تجویز/بازخورد (M40-c1)

تاریخ: ۱۴۰۵/۰۸/۲۴ (2026-11-14) — نسخهٔ pilot-1.0
مالک: محقق (فین) — بازبینی: مالک باشگاه

## هدف
تأیید حلقهٔ کامل در استفادهٔ واقعیِ کنترل‌شده: ثبت آزمون ← ماتریس ۱۴ محور ← تجویز
محور-آگاه ← بازخورد ست (RIR/درد) ← تعدیل جلسهٔ بعد — با معیارهای از پیش تعریف‌شده.

## شرکت‌کنندگان
- ۳–۵ نفر داخلی (همکاران/دوستان باشگاه — داوطلب، رضایت آگاهانه ثبت‌شود)
- نقش‌ها: ۱ مربی (ثبت آزمون/بازبینی)، ۱ ادمین (مشاهدهٔ داده‌ها)

## روزشمار
| روز | فعالیت | خروجی |
|---|---|---|
| ۱ | ثبت‌نام + آزمون پایهٔ ۱۴ محور | baseline matrix |
| ۲–۶ | تمرین طبق تجویز + بازخورد هر ست (RIR/درد) | set_feedbacks |
| ۷ | ماتریس پایان + مقایسه + مصاحبهٔ کوتاه | گزارش + بازخورد کیفی |

## معیارهای موفقیت (از پیش تعریف‌شده — جلوگیری از تفسیر پسینی)
- ≥ ۸۰٪ ست‌ها بازخورد کامل (RIR یا درد) داشته باشند
- صفر خطای سمت کاربر (وضعیت 5xx یا عدد نامعلوم در UI — «—» قابل قبول است)
- ≥ ۶۰٪ کاربران «دلیل تغییر» را قابل فهم ارزیابی کنند (مصاحبهٔ روز ۷)
- همهٔ تعدیل‌ها reason داشته باشند (۱۰۰٪ — خودکار در rule-evidence)

## مرزهای ایمنی پایلوت
- شرکت‌کنندگان سالم؛ وجود هر red-flag = خروج از پایلوت + ارجاع
- داده‌ها در دیتابیس داخلی؛ هیچ PII در Git (E09)
- عدالت: همهٔ شرکت‌کنندگان به همان قواعد نسخه‌دار (axis-prescription-1.0 / set-feedback-1.0) تکیه می‌کنند — نه ترجیح شخصی مربی

## dry-run مهندسی (همین نشست)
حلقهٔ کامل به‌صورت تست E2E خودکار اجرا می‌شود (tests/integration/test_pilot_dry_run.py)
تا مسیرهای API پیش از تماس انسانی اثبات شده باشند. نتیجه در
`finn/reports/evidence/M40-pilot-dryrun.rule-evidence.json` ثبت می‌شود.
