# سیاست دادهٔ بیومتریک Muscle Paradise (M09)

> اصل: **رضایت، حداقل‌سازی، شفافیت، حق حذف** — الهام‌گرفته از GDPR + قوانین داخلی در حال شکل‌گیری

## ۱. چه چیزی ذخیره می‌شود
- فقط **embedding رمزنگاری‌شده** (خروجی SFace، PyNaCl SecretBox) — نه تصویر، نه embedding خام
- رکورد **رضایت‌نامه** (نسخهٔ سیاست، زمان اعطا/لغو)

## ۲. رضایت آگاهانه (US-108)
1. نمایش متن رضایت‌نامه با نسخهٔ مشخص
2. تأیید صریح (کلیک/لمس) — رضایت ضمنی ممنوع
3. بدون رضایت فعال، ثبت چهره **غیرممکن** است (تست‌شده)

## ۳. حداقل‌سازی
- embedding فقط برای تطبیق یک‌به‌یک در گیت ورود استفاده می‌شود
- هیچ انتقال دادهٔ بیومتریک به سرویس خارجی/ابری وجود ندارد (local-first)

## ۴. حق حذف (حقوق فرد)
- حذف چهره: یک‌کلیکی از اپ عضو یا پنل مدیر → حذف قطعی رکورد
- لغو رضایت = حذف خودکار چهره + غیرفعال‌شدن ورود چهره (fallback به QR)
- حذف غیرقابل‌بازگشت است؛ فقط audit log (بدون دادهٔ بیومتریک) باقی می‌ماند

## ۵. امنیت
- کلید رمزنگاری از `MP_BIOMETRIC_KEY` (env، خارج از مخزن)
- دسترسی DB محدود؛ بکاپ restic رمزنگاری‌شده
- هر عملیات ثبت/حذف چهره در audit log (US-406)

## ۶. نگهداری
- رضایت‌نامه‌ها تا پایان رابطهٔ عضویت + ۶ ماه (بازهٔ قانونی) نگهداری می‌شوند؛ سپس حذف
- درخواست حذف حداکثر ۳۰ روز اجرا می‌شود (US-407)
