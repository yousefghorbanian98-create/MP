## توصیه — گزینهٔ یک: یک برنامه + admin pass نقش‌محور

«admin pass» همان **نقش** است (`manager` / `admin` / `super_admin`) با این قواعد:
1. اعطا/ابطال نقش فقط توسط `super_admin` (قابل افزودن به Settings استودیو).
2. هر دسترسی فراتر از عضو = نقش + لاگ ممیزی (US-406 — `GET /admin/audit`).
3. گوشی اعضا همان اپ است؛ با نقش ادمین، منوهای مدیریتی باز می‌شود (session کوتاه‌عمر).
4. **استودیو** (دسکتاپ میز پذیرش) باقی می‌ماند — نیاز عملیاتی واقعی پذیرش/کیوسک، نه محصول دوم.

## نقشهٔ راه ادمین (M42 — ثبت‌شده در BUILD-QUEUE)
- c1 ✅: لیدربوردها (بهترین ورزشکار / بیشترین هزینه / بیشترین مراجعه) — `GET /admin/analytics/leaderboards`
- c2 ✅: ثبت خروج + «بیشترین تایم» (مجموع دقیقهٔ جلسات بسته)
- c3 ✅: صفحهٔ «تحلیل‌ها» در استودیو + همین سند
- **شکاف‌های آینده (ثبت‌شده، نه ادعاشده)**: churn/retention (الگوی Glofox)، گزارش کارکرد مربیان (زمان‌پرداز)، اعطای نقش در UI، اتصال کامل استودیو به API (فعلاً فقط صفحهٔ تحلیل‌ها زنده است).
