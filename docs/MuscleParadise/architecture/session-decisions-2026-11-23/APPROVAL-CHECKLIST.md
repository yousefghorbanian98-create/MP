# برگهٔ بازبینی مالک — پیش از رسمی‌شدن معماری

این چک‌لیست برای **تأیید محتوای پیشنهادی** است، نه اینکه با سکوت تأیید فرض شود. تا وقتی پاسخ روشن نیاید، نمودار/بسته draft می‌ماند و وارد `architecture/README.md` یا ADR قطعی نمی‌شود.

## A. تأیید صحت و دقت وضعیت

برای هر ردیف یکی را انتخاب/بنویسید: `تأیید` / `اصلاح: ...` / `باز بماند`.

- [ ] نقش‌های جاری در نمودار: `member`, `coach`, `reception`, `manager`, `admin`, `super_admin`.
- [ ] کلاینت انتشار اول: Flutter/Android برای عضو + Studio وب برای کارکنان؛ PWA فعلاً فقط هدف قدیمیِ تأییدنشده است.
- [ ] محل محصولیِ انتشار اول: سرور محلی باشگاه + ورودی HTTPS؛ exact host/domain/tunnel/backup/deploy هنوز اثبات نشده.
- [ ] فروشگاه عضو: catalog/display-only، online checkout پیش‌فرض خاموش و API fail-closed.
- [ ] پرداخت انتشار اول: کارت‌به‌کارت + فیش خصوصی + بازبینی انسانی/تطبیق بانکی مستقل؛ درگاه live فعال فرض نشده.
- [ ] حضور: QR کوتاه‌عمر + قفل محلی دستگاه؛ مسیر چهرهٔ سروری فعال فرض نشده و ۴۰۹ را گپ/حالت امن ثبت می‌کنیم.
- [ ] safety: blocked/unknown هنوز draft/نمایش‌شدن ممکن است؛ به‌عنوان fail-closed کامل معرفی نشود.
- [ ] body progress photo: خارج از scope انتشار اول؛ در قابلیت آینده مدت را عضو انتخاب می‌کند؛ این دو ادعا جدا ثبت شوند.
- [ ] SQLite default در source؛ PostgreSQL تصمیم قطعی/مهاجرت‌شده نیست.
- [ ] Worker/scheduler تعریف‌شده‌اند؛ فعال بودن runtime در startup یا production اثبات نشده.

## C. پرسش‌های معماری که به تصمیم تازه نیاز دارند

این موارد در سند فعلی عمداً «باز»ند؛ انتخاب پیش‌فرض از طرف ایجنت ثبت نشده است.

| موضوع | وضعیت فعلی ثبت‌شده | گزینهٔ نیازمند تصمیم |
|---|---|---|
| PWA | هدف/نمودار قدیمی، نه محصول جاری | فقط بررسی feasibility؛ یا مهاجرت انتخابی؛ یا فعلاً بدون PWA. هر گزینه، مرز Flutter/Studio و معیار پذیرش داشته باشد. |
| نقش‌های مقصد | ۶ role جاری؛ مالکیت super_admin-only و grantهای محدود در اسناد قبلی | حفظ ۶ role؛ یا تأیید طراحی مدل ۳ role به‌عنوان target (به معنی rename/migration فوری نیست). |
| DB | SQLite default؛ PostgreSQL هدف مشروط | معیار بار/همزمانی و آزمون/ADR/rollback را تعیین کنید؛ یا تا جمع‌آوری داده SQLite بماند. |
| استقرار | سرور محلی + HTTPS ingress جهت مصوب | میزبان/دامنه/تونل/بودجه/مسئول عملیات فقط پس از استعلام؛ قبل از آن هیچ خرید یا استقرار اجرایی انجام نمی‌شود. |
| عکس بدن | feature انتشار اول خارج از scope؛ retention آینده را عضو تعیین می‌کند | اگر قرار است برای نسخهٔ بعد وارد scope شود، زمان تصمیم را مشخص کنید؛ نوع رضایت، حذف، backup و حقوقی هنوز طراحی لازم دارد. |
| گزارش مالی | حالت ناقص سود را نامعلوم می‌کند | تعریف دورهٔ مالی، سود، refund، هزینه و مرز گزارش مدیریتی با حسابدار/مالک. |
