# پرسش‌نامهٔ تصمیم‌های مالک و ثبت پاسخ‌ها — Muscle Paradise

**وضعیت:** پاسخ‌های دور اول و پیگیری ثبت شدند. PWA مشترکِ عضو و کادر برای انتشار اول انتخاب شد و Android/Flutter حفظ می‌شود؛ هدف مرورگر Android Chrome برای عضو و Chrome/Edge دسکتاپ برای کادر است. SQLite و نبود inference بیرونی انتخاب شده؛ owner گفته reviewer مستقل ندارد. نسخه‌های دقیق مرورگر/دستگاه، میزبان/اپراتور، بودجه و backup/RPO/RTO هنوز بازند. این فایل دفتر پاسخ است و به‌تنهایی مجوز release یا deploy نیست. رجیستر یگانهٔ open-decisionها و evidence لازم در [TODO اجرایی PWA جاری](../TODO-PWA-RELEASE-2026-11-23.fa.md) نگهداری می‌شود؛ گزینه‌های پاسخ‌داده‌شده در این دفتر دوباره باز نمی‌شوند.

## روش پاسخ‌گویی و ادامهٔ کار

- پاسخ‌های انتخاب‌شده در question boxهای دور اول این گفتگو، با وضعیت دقیق و بدون استنباط در جدول «دفتر پاسخ‌ها» ثبت شدند. درخواست توضیح یا پاسخ ناقص همچنان `PENDING/PARTIAL` است؛ از سکوت یا انتخاب ناقص تصمیم استنباط نمی‌شود.
- به هیچ وجه رمز، token، کلید امضا، اطلاعات مالی محرمانه یا دادهٔ واقعی عضو را در پاسخ ننویسید. برای تعیین وضعیت APK فقط بگویید توزیع شده/نشده/نامعلوم.
- وقتی بگویید **«ادامه بده»**، کارهای آماده و مستقل را روی شاخهٔ فعال `arena/5e0f64cf-mp` بدون مکث برای تأییدهای روتین ادامه می‌دهم: کدنویسی محدود، تست، مستندات و ثبت شواهد. بین پیام‌ها کار پس‌زمینه اجرا نمی‌کنم. تغییرهای موجود worktree حفظ می‌شوند؛ شاخه عوض نمی‌شود.
- تصمیم حقوقی/تجاری/محصولیِ غیرقابل‌حدس، دستگاه یا حساب بیرونیِ در دسترس‌نبودنی، و گیت امنیت/حریم/ایمنی با حدس رد نمی‌شود؛ همان وابستگی `BLOCKED/UNKNOWN` ثبت می‌شود و کارهای مستقل ادامه می‌یابند.
- تا مجوز صریح و محدود، این دستور ادامه شامل commit/push/PR/merge، release/deploy، پرداخت واقعی، secret، عملیات روی DB تولیدی یا پاک‌سازی فایل‌ها نیست. این پرسش‌نامه هم production را خودکار مجاز نمی‌کند.

## تصمیم‌های قبلاً ثبت‌شده در اسناد پروژه

این‌ها به‌عنوان baseline موجود نقل شده‌اند، نه پاسخ تازهٔ این پرسش‌نامه. فقط اگر قصد تغییر دارید، در سؤال مربوطه گزینهٔ اصلاح/custom را انتخاب کنید:

- پرداخت انتشار اول: کارت‌به‌کارت با تطبیق انسانی؛ فروشگاه عضو نمایش‌محور و خرید آنلاین خاموش؛ gateway زنده به merchant و تصمیم جدا نیاز دارد.
- حضور: QR؛ تشخیص چهره در محصول/انتشار اول فعال یا وعده داده نشود.
- راهنمای سلامت، تشخیص یا جایگزین پزشک نیست؛ عکس پیشرفت بدن در scope انتشار اول نیست.
- اعطای نقش/مجوز به `super_admin` محدود است؛ شش نقش فعلی در کد حفظ‌اند، درحالی‌که مدل سه‌نقشیِ طرح PWA هنوز تصمیم/نگاشت مصوب نیست.
- baseline قبلیِ کلاینت، Android عضو + Studio وب بود؛ پاسخ مالک در OQ-01 آن را برای انتشار اول به **PWA اصلی** تغییر داد، با حفظ Flutter/Android. رجیستر جاری آن در [TODO اجرایی PWA](../TODO-PWA-RELEASE-2026-11-23.fa.md) آمده است؛ پیاده‌سازی/parity/QA فنی همچنان کار مستقل است.
- جهت زیرساخت ثبت‌شده و تازه‌تأییدشده، سرور محلی باشگاه با ورودی HTTPS است؛ میزبان دقیق، هزینه، مسئولیت، backup و restore اثبات/تعیین نشده‌اند.
- توزیع مستقیم APK قبلاً ثبت شده بود؛ مالک گفته نسخهٔ انتشار APK به کاربران توزیع نشده است. این پاسخ وضعیت توزیع را ثبت می‌کند، اما خود کلید افشاشده را امن نمی‌کند؛ مسیر rotate/تولید امن همچنان لازم است.
- دربارهٔ بازبینی تخصصی، مالک گفته فعلاً فقط خودش مسئول محصول است و reviewer مستقل حقوقی/پزشکی/مالی ندارد؛ ادعاها و قابلیت‌های حساس باید در مرز امن ثبت‌شده بمانند و گیت نیازمند بازبینی مستقل بدون شاهد `UNKNOWN/BLOCKED` است.

## راهنمای question boxها

### باکس ۱ — معماری و اختیار اجرا (OQ-01 تا OQ-06)

1. **پلتفرم انتشار اول:** Android عضو + Studio وب را نگه‌دار؛ PWA فقط مسیر آینده باشد / PWA را کنار آن‌ها هم وارد انتشار اول کن / PWA را مقصد انتشار اول کن ولی Flutter/Android را حفظ کن / پاسخ سفارشی.
2. **میزبانی و عملیات:** سرور محلی + HTTPS را نگه‌دار و تا تعیین میزبان/مسئول/هزینه/backup/restore deploy نکن / Full Cloud را به‌عنوان جهت تازه انتخاب کن ولی خرید و deploy را جدا نگه‌دار / فعلاً فقط محیط تست و توسعه / پاسخ سفارشی با مسئول و سقف هزینه.
3. **باشگاه و نقش‌ها:** تک‌باشگاه و حفظ شش نقش فعلی / multi-tenant برای انتشار اول / مدل سه‌نقشی را فقط به‌عنوان target تأیید کن (بدون migration خودکار) / پاسخ سفارشی.
4. **DB:** SQLite تا اندازه‌گیری بار و تعیین معیار مهاجرت / طراحی PostgreSQL برای انتشار اول، بدون تغییر DB تولیدی تا migration و rollback آزموده / فعلاً تصمیم را عقب بینداز / پاسخ سفارشی با آستانه.
5. **خودمختاری Git:** ادامهٔ خودکار روی worktree و تست‌ها، بدون commit/push/PR/merge/release/deploy / اجازهٔ commit و push فقط به شاخهٔ جاری پس از گیت‌ها، بدون merge و deploy / draft PR روی همین شاخه / پاسخ سفارشی با محدودهٔ دقیق. «ادامه بده» به‌خودی‌خود کار پس‌زمینه یا مجوز production نیست.
6. **مدل و داده:** بدون API/inference بیرونی؛ فقط ابزار قطعی و مدل محلیِ از قبل مجاز/در دسترس / API بیرونی فقط برای دادهٔ عمومیِ پالایش‌شده با بودجه و provider مشخص / فعلاً قابلیت‌های وابسته به مدل `BLOCKED` بمانند / پاسخ سفارشی. هیچ کد/دادهٔ خصوصی با انتخاب کلی به سرویس بیرونی ارسال نمی‌شود.

### باکس ۲ — انتشار، محصول و مسئولیت‌ها (OQ-07 تا OQ-10)

7. **baseline حساس محصول:** ثبت‌شده‌ها را تأیید کن (تطبیق انسانی کارت‌به‌کارت، فروشگاه نمایش‌محور، QR و بدون تشخیص چهره، راهنمای غیرپزشکی، بدون عکس بدن در انتشار اول) / یک یا چند مورد را دقیقاً اصلاح کن / تا بازبینی متخصص، همهٔ موارد حساس خارج از scope بمانند / پاسخ سفارشی.
8. **دامنهٔ انتشار و شاهد:** تمام جریان‌های اصلیِ TODO و گیت‌های امنیت/حریم/backup/device قبل از release لازم‌اند / scope را به MVP محدود کن و موارد حذف‌شده را نام ببر (نیازمند اصلاح رسمی معیار Go/No-Go) / فعلاً scope را تعیین نکن و فقط توسعهٔ امن ادامه یابد / پاسخ سفارشی شامل دستگاه‌های هدف و جریان‌ها.
9. **کلید APK افشاشده:** هنوز APK انتشار به کاربر نداده‌ایم / نسخهٔ امضاشده به کاربران رسیده و به‌روزرسانی بی‌وقفه لازم است / وضعیت نامعلوم است و باید اول تاریخچهٔ توزیع بررسی شود / پاسخ سفارشی. هیچ‌وقت رمز یا خود کلید را نفرستید.
10. **حریم/بازبینی تخصصی:** مسئول مشخص دارید (فقط نقش/نام غیرمحرمانه و دامنه را بنویسید) / مسئول ندارید، پس قابلیت‌های پزشکی/عکس/دادهٔ حساس تا تعیین متخصص خارج از scope و release متوقف بماند / نیازمند استخدام/تعیین متخصص و بودجه است / پاسخ سفارشی.
