# یک‌دست‌سازی شاخه‌ها در `main` — ۲۰۲۶-۱۱-۲۰

> هدف: **`main` تنها منبع حقیقت** باشد؛ هیچ شاخهٔ کاری موازی با محتوای قدیمی باقی نماند،
> و هر چیزی که ارزش بازیابی دارد با **تگ آرشیو** حفظ شود، نه با مرج.

## ۱. مسئله

سه شاخهٔ دوردست علاوه بر `main` باقی مانده بودند که هر سه از `main` عقب بودند.
مرج شاخهٔ عقب‌افتاده «هم‌گام‌سازی» نیست: Git از سه‌راهی ترکیب می‌کند، پس

- کار جدید `main` پاک نمی‌شود، ولی
- کامیت‌های یکتای شاخه وارد `main` می‌شوند (حتی اگر نسخهٔ قدیمی یک قابلیت باشند)،
- فایل‌هایی که `main` عمداً حذف کرده و شاخه هنوز دارد **برمی‌گردند**،
- و هر فایلی که دو طرف تغییر داده‌اند کانفلیکت دستی می‌سازد.

## ۴. کاری که انجام شد

1. سه تگ آرشیو (annotated) ساخته و push شد — tip، تاریخ و هشدار محتوا در پیام تگ:
   - `archive/arena-86fc9529-mp` → `5a9789b7`
   - `archive/arena-a0408b29-mp` → `d7d3a586`
   - `archive/arena-4f336f66-mp` → `54829305`
2. شاخه‌های دوردست حذف شدند: `arena/86fc9529-mp`، `arena/a0408b29-mp`، `arena/4f336f66-mp` و `arena/3b2b9471-mp` (این آخری با PRهای #11/#12 کاملاً در `main` است: `85e9875`).
3. نتیجه: `git ls-remote --heads origin` فقط `main` را نشان می‌دهد؛ `main` تنها منبع حقیقت است.

بازیابی در صورت نیاز:

```bash
git fetch origin tag archive/arena-86fc9529-mp
git show archive/arena-86fc9529-mp:path/to/file.py     # خواندن یک فایل
git switch -c recover/86fc9529 archive/arena-86fc9529-mp   # شاخهٔ موقت برای مرور
```

> هشدار: در تگ‌های ۸۶ و a0408 **کلید keystore و APK** وجود دارد. هرگز آن شاخه را
> یک‌جا مرج نکن؛ فقط فایل مشخص و پس از بازبینی جدا شود.

## ۵. قاعدهٔ آینده

| وضعیت شاخه | کار درست |
|---|---|
| کاملاً زیر `main` (۰ کامیت یکتا) | حذف؛ مرج بی‌اثر است |
| کار یکتا دارد و عقب است | `git rebase main` (تاریخ خطی) یا cherry-pick کامیت‌های منتخب؛ سپس PR و CI |
| می‌خواهی فقط هم‌گام شود | `main` را **به داخل شاخه** بیاور (`git merge main`)، نه برعکس |
| رها شده ولی ارزش مرجع دارد | تگ آرشیو + حذف شاخه (همین کاری که شد) |

هیچ‌کدام از این‌ها جای CI و `repo_hygiene_gate` را نمی‌گیرد: نتیجهٔ نهایی همیشه باید روی
همان SHA در CI سبز شود.
