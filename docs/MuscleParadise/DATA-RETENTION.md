# سیاست نگهداری، اصلاح و حذف داده (E10) — نسخهٔ ۱ — ۲۰۲۶-۱۱-۱۴

> وضعیت: **پیش‌نویس مصوب مهندسی — اجرا پیش از ورود دادهٔ واقعی الزامی است.**

## اصول
1. **حداقل‌سازی:** فقط دادهٔ هدف‌مند و مجاز (تصمیم قطعی کاربر + §۴ بستهٔ handoff).
2. **هدف/رضایت:** هر پردازش با نسخهٔ فرم رضایت ثبت‌شده (M10) — تغییر هدف = رضایت جدید.
3. **طبقه‌بندی:** (الف) هویت/تماس (ب) سلامت/پیکرسنجی/علائم — حساس (ج) مالی (د) رفتار/حضور.
4. **دسترسی:** عضو فقط دادهٔ خود (مالکیت سطری M18)؛ staff طبق نقش؛ **لاگ دسترسی به دادهٔ حساس** (M31).

## نگهداری
| داده | مدت پس از پایان عضویت | سپس |
|---|---|---|
| هویت/تماس | ۲۴ ماه (تمدید/بازگشت) | حذف/بی‌نام‌سازی |
| اندازه‌گیری/پیکرسنجی | ۳۶ ماه (روند پژوهشی) | بی‌نام‌سازی (بدون نام/تلفن) |
| مالی/پرداخت | ۶۰ ماه (الزام حسابداری ایران) | بایگانی رمزنگاری‌شده |
| حضور/چک‌این | ۱۲ ماه | حذف |
| لاگ امنیتی/audit | ۱۲ ماه | حذف |
| چهره (FaceTemplate) | تا لغو رضایت — هر لحظه | حذف قطعی الگو (نه تصویر — تصویر اصلاً ذخیره نمی‌شود) |

## اصلاح/حذف
- درخواست عضو (از اپ/استودیو) → ثبت درخواست → اجرای staff ≤ ۳۰ روز → رسید.
- حذف = حذف فیزیکی/بی‌نام‌سازی؛ snapshot برنامه‌های قبلی **بدون هویت** باقی می‌ماند (E02/گزارش).
- بکاپ‌ها: چرخهٔ ۹۰ روزه (بکاپ‌های قدیمی‌تر خودکار پاک شوند) — حذف درخواستی در اولین چرخهٔ بکاپ به بکاپ‌ها هم سرایت می‌کند.

## فنی
- رمزگذاری در حالت سکون: disk-level (LUKS/BitLocker سرور محلی) + رمزنگاری FaceTemplate (کلید `MP_BIOMETRIC_KEY`).
- انتقال: HTTPS داخلی (M28)؛ هیچ egress بیرونی (E11).
- بکاپ/بازیابی: `scripts/backup.py` (M23-c2) — drill بازیابی در M30.
