## اصل اجرای خودمختار — D-033، ۲۰۲۶-۱۱-۱۶

این نقشه اجرای محلی اصل سراسری D-033 است؛ همان قاعده برای همهٔ بازه‌های TODO صدق می‌کند، نه فقط M63–M99. loopهای M63–M99 که در این نقشه `READY` هستند بدون توقف برای نظارت/تأیید روتین پیش می‌روند. عامل تصمیم فنیِ محدود و برگشت‌پذیر را با پیش‌فرض امن می‌گیرد و دلیل/شاهد/اثر بازگشت را در `.finn/state/DECISIONS.md` و گزارش همان loop می‌نویسد. سؤال‌پرسیدن یا `WAITING_FOR_REVIEW` برای گرفتن نظر روتین، مجاز نیست.

اگر پیش‌نیاز واقعی بیرونی/حقوقی/امنیتی، مالکیت credential، دستگاه، مجوز یا تصمیم تجاریِ غیرقابل‌حدس لازم باشد، همان loop `BLOCKED`/`UNKNOWN` می‌ماند؛ بدون سؤال یا حدس، به loop مستقل بعدی می‌رویم. هیچ gate/tests/threshold حذف نمی‌شود و `PASS` فقط با شاهد ثبت می‌شود. این اصل ممنوعیت‌های همین نقشه—به‌ویژه no push/release/deploy، no production DB و no real payment/data—را تغییر نمی‌دهد.

## قرارداد اجرای این بازه

1. ترتیب عادی **M63 → M99** است. هر loop یک دامنهٔ محدود، وابستگی، فایل‌های مجاز، معیار پذیرش و شاهد دارد. پایان هر loop با `PASS`, `FAIL`, `BLOCKED` یا `UNKNOWN` ثبت می‌شود؛ «شروع‌نشده» معادل انجام‌شده نیست.
2. ابتدا baseline و `git status` تازه خوانده می‌شود؛ آثار موجود/`untracked` حفظ می‌شود. فقط فایل‌های همان loop تغییر می‌کنند. یک blocker فقط همان loop و وابستگان مستقیمش را متوقف می‌کند؛ loopهای مستقل ادامه می‌یابند.
3. باگ امنیتی فقط بعد از بازتولید با تست/شاهد جاری «تأییدشده» نام می‌گیرد. اگر تأیید شد: تست رگرسیون، کوچک‌ترین اصلاح، سپس اجرای دوبارهٔ همان تست و مسیرهای مرتبط. برای یک علت حداکثر سه تلاش؛ بعد از آن فقط تغییرهای همان loop کنار گذاشته/quarantine می‌شوند، نه کل workspace.
4. هیچ تستی skip/پنهان نمی‌شود، آستانه پایین نمی‌آید، و بدون شاهد `PASS` ثبت نمی‌شود. نبودن executable محلی به‌تنهایی blocker پروژه نیست؛ برای Flutter از mirror موردتأیید یا CI استفاده می‌شود. اگر اجرای CI مستلزم push باشد، push انجام نمی‌شود و وضعیت شاهد `UNKNOWN` می‌ماند.
5. ممنوع در این بازه: push، release، deploy/rollback، تغییر DB تولید، پرداخت واقعی و استفاده از داده/credential واقعی اعضا. هیچ `git reset --hard` یا پاک‌سازی workspace مجاز نیست. هیچ نصب ECC/REA یا ادعای اجرای subagent در این نقشه مفروض نیست.
6. بازبینی‌های ECC (`planner`, `architect`, `tdd-guide`, `code-reviewer`, `security-reviewer`, `build-error-resolver`, `silent-failure-hunter`, `pr-test-analyzer` و متخصص مرتبط) فقط وقتی به‌عنوان review-pass ثبت می‌شوند که واقعاً متن نقش/چک‌لیست مربوطه اجرا و نتیجهٔ آن ثبت شده باشد؛ خواندن فایل نقش به‌تنهایی اجرای ایجنت نیست.
7. «کامل/بی‌نقص» تضمین نمی‌شود. `M99` گزارش شواهد و blockerهاست، نه اجازهٔ انتشار.
