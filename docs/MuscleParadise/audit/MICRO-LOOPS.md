# ریز‑حلقه‌های خودکفای ممیزی (MICRO-LOOPS)

> سند عملیاتی حلقهٔ FINN برای اجرای بی‌ناظر. هر اجرای جدید **از همین‌جا و از `FINN-AUDIT-LOOP.md` شروع می‌کند**، نه از حافظهٔ گفتگو.
> شاخه: `arena/da474b65-mp` · صف و وضعیت: `FINN-AUDIT-LOOP.md` · تصمیم‌ها: `DECISIONS.md` · رکورد: `EXECUTION-LOG.md`.

## ۱. اختیار حلقه

**حلقه بی‌وقفه کار می‌کند.** پس از هر ریز‑حلقهٔ `DONE` بلافاصله ردیف `READY` بعدی را برمی‌دارد. پرسیدن از مالک فقط در موارد ۳ می‌آید.

### ۱‑الف · تصمیم‌های خودکار (بدون پرسش)
هر ابهامی که درون دامنهٔ WP است و برگشت‌پذیر است، با **پیش‌فرض امن** حل می‌شود و در `DECISIONS.md` با شماره‌ی `AD‑n` (یا `BD‑n` برای بریف) ثبت می‌شود. هر تصمیم سه چیز دارد: زمینه، گزینه‌ی انتخابی و گزینه‌ی ردشده، و نحوهٔ برگرداندن.

نمونه‌ها: ترتیب بین دو WP، سیاست لاگ، مقدار پیش‌فرض کانفیگ، نام helper، اعداد آستانه‌ای که بریف نداده.

### ۱‑ب · قواعد غیرقابل‌مذاکره
1. **گیت قرمز رد نمی‌شود.** skip، ignore، پایین‌آوردن آستانه یا تضعیف گیت ممنوع (G2 و §۳‑۲ الحاقیه).
2. **قرمز‑اول.** برای هر باگ، تست رگرسیون پیش از اصلاح قرمز دیده می‌شود. اگر دیده نشد، صراحتاً در `EXECUTION-LOG.md` نوشته شود (G3).
3. **حداکثر سه تلاش برای یک خطا (G4).** پس از آن `BLOCKED` با شاهد.
4. **ادعا فقط با شاهد.** فرمان، exit code، شمارش.
5. **یک کامیت برای هر ریز‑حلقه،** push فقط به `arena/da474b65-mp`، بدون force. هیچ artifact (`var/receipts` تازه، `share/`، `dist/`) وارد commit نمی‌شود.
6. **`git add -A` ممنوع** در این حلقه؛ فقط مسیرهای مشخص.

### ۱‑پ · توقف واقعی (تنها موارد)
| کد | معنی | اقدام |
|---|---|---|
| `HARD-STOP-FIN` | تصمیم مالی/حقوقی یا قیمت که بریف پاسخ نمی‌دهد | WP را رد کن؛ سؤال **بسته** بنویس؛ ادامه بده |
| `HARD-STOP-SCHEMA` | migration تازه یا تغییر schema (به‌جز F‑22 در WP 4.5) | همین |
| `HARD-STOP-PRODUCT` | تصمیم محصولی خارج از پنج تصمیم پرامپت + D‑6/D‑7 | همین |
| `HARD-STOP-DEP` | bump نسخهٔ وابستگی (ruff باید `0.17.x` بماند) | همین |
| `HARD-STOP-GIT` | force push، تغییر branch protection، merge بدون تأیید | همین |
| `BLOCKED-ENV` | منبعی که در sandbox نیست (Docker، Postgres، Prometheus، دستگاه، امضای APK، استقرار زنده) | WP را `BLOCKED-ENV` کن؛ شاهد جایگزین اگر هست؛ ادامه |

**هیچ‌کدام از این‌ها توقف کل حلقه نیست.** فقط همان WP متوقف می‌شود و حلقه به WP مستقل بعدی می‌رود.

## ۲. قالب یک ریز‑حلقه

هر WP دقیقاً این مراحل را طی می‌کند:

| # | مرحله | خروجی الزامی |
|---|---|---|
| 1 | **پیش‌سنجش:** `git status`، `git log -3`، شاهد «قبل» (فرمان + خروجی) | خروجی خام |
| 2 | **قرمز:** تست رگرسیون که قبل از اصلاح ناموفق است، روی کامیت پیش از تغییر | خروجی ناموفق |
| 3 | **اصلاح:** کوچک‌ترین تغییری که قرمز را سبز می‌کند | diff |
| 4 | **سبز:** تست هدف + مرتبط + گیت عددی بریف | خروجی سبز |
| 5 | **سلامت:** `ruff check` و `ruff format --check` روی تغییرها؛ `verify-addendum-gates.sh` در stage مربوطه | PASS |
| 6 | **pytest کامل** (اگر پایان فاز یا تغییر در مسیر پول/احراز/SMS) | `N passed, M skipped, exit 0` |
| 7 | **ثبت:** `status.json`، `FINN-AUDIT-LOOP.md`، `EXECUTION-LOG.md`، `DECISIONS.md` | commit |
| 8 | **کامیت و push** (مسیرهای مشخص) + `build_audit_inventory.py --check` پس از کامیت | `git ls-remote` |

**قالب رکورد (EXECUTION-LOG، بدون فیلد خالی):**
```text
WP: <id> · F: <id> · برچسب: <نام> ≡ <نام سند>
commit: <sha>
فرمان‌ها: <عیناً>
قرمز: <خروجی ناموفق>
سبز: <خروجی>
گیت‌ها: <PASS/ACTION + خروجی>
انحراف از سند: صفر | <مورد + دلیل + AD-n>
توقف‌ها: هیچ | <کد + سؤال بسته>
```
