### قید دامنهٔ محصول — مخاطب ایرانی

**تصمیم محصولی:** مخاطب این اپ ایرانی است. پایگاه تغذیه نباید با غذای آماده/ترکیبیِ ملت‌ها و آشپزی‌های دیگر پُر شود. منبع M4/G12 باید غذاها و وعده‌های رایج ایرانی، نام‌گذاری فارسی و واحد/portion قابل‌فهم برای عضو ایرانی باشد؛ مادهٔ خام عمومی فقط وقتی وارد می‌شود که برای محاسبهٔ غذای ایرانی لازم باشد و منبع، مقدار و مجوزش روشن باشد. دیتاست عمومی خارجی را برای پُرکردن تعداد رکوردها وارد نکن.

**معیار پذیرش M4/G12:** ثبت و نمایش غذای ایرانی از پایگاه موجود MP؛ جمع روزانه/مقدار مصرف درست؛ نام و واحد فارسی؛ منشأ/مجوز داده قابل ردیابی. دستورهای پیچیدهٔ غیرایرانی نباید در کاتالوگ قرار گیرند. `FitBook` فقط مرجع احتمالیِ کد/جریان UI است، نه منبع غذا: README آن دیتای ۷هزار قلم را به CORGIS نسبت می‌دهد و metadata گیت‌هاب برای مخزن CORGIS مجوز GPL-3.0 نشان می‌دهد؛ دیتای آن وارد نشود. Open Food Facts هم کاتالوگ محصول/barcode است، نه پایگاه دستور غذای ایرانی، و مجوز داده‌اش باید جدا بررسی شود.

##### معیارهای پذیرش گروهی دست‌نخورده (handoff PWA)

این پنج سفر با همان معنا حفظ می‌شوند؛ آن‌ها جای ۵۰ parent را نمی‌گیرند و با mock/presentation pass نمی‌شوند:

1. **عضو:** OTP → پروفایل خودش → برنامهٔ تأییدشده → ثبت اجرای واقعی/feedback → reload و تأیید وضعیت سرور.
2. **مربی:** ورود → انتخاب عضو مجاز → ارزیابی → draft برنامه → review/تأیید با دلیل → همان نسخه برای عضو.
3. **حضور:** عضو/پذیرش → QR → اعتبارسنجی server-side → رد token منقضی یا تکراری.
4. **مالی:** عضو receipt ارسال کند → کارمند مجاز بررسی کند → نتیجه و audit؛ receipt ≠ bank approval.
5. **امنیت:** member A نتواند route/API/رسید/پیام/data عضو B را بخواند؛ hidden button یا تغییر URL هیچ مجوزی نمی‌دهد.
