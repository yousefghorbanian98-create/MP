```python
def list_payments(
    db: Session, member_id: int | None = None, status: str | None = None, user=None
) -> list[Payment]:
    if user is not None and user.role == "member":
        from app.security.ownership import get_own_member

        own = get_own_member(db, user)
        member_id = own.id if own else -1
    stmt = select(Payment).order_by(Payment.id.desc())
    if member_id is not None:
        stmt = stmt.where(Payment.member_id == member_id)
    if status is not None:
        stmt = stmt.where(Payment.status == status)
    return list(db.scalars(stmt))
```
⇒ عضو با `GET /payments` فقط ردیف‌های خودش را می‌بیند؛ UI هیچ `member_id` نمی‌فرستد.

## نتیجه (پاسخ صریح)
- آپلود فیش: `POST /payments/{id}/receipt` → **202** با `status="in_review"`،
  `review_id` و `expires_at` (۴۸ ساعت). این «تأیید بانک» نیست.
- محدودیت‌ها سمت سرور: ۵ مگابایت، فقط JPEG/PNG/WebP، و **سنجش محتوای فایل**
  (نوع اعلام‌شده با محتوا باید بخواند) — کلاینت فقط پیش‌فیلتر می‌کند.
- فقط `card_to_card` + `pending` مسیر فیش دارد؛ هر چیز دیگر کد `receipt_not_applicable`
  یا `already_processed` می‌گیرد.
- BLOCKED (پول، اجباری): تأیید فیش با مرجع بانکی مستقل و فعال‌سازی اشتراک تصمیم
  فرد مجاز/مالی است؛ UI عضو هیچ دکمهٔ تأیید/رد ندارد و ادعای «پرداخت شد» نمی‌کند.
